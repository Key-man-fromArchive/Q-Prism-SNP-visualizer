## 2. 루트 미커밋 변경의 처리 방침 — **조치 불필요**

작업서는 루트의 `M .gitignore` / `D node_modules` / `?? .claude/` 처리 방침 확정을 요구했다.
확인 결과 **셋 다 이미 main에 반영된 상태**이며, 루트가 5커밋 뒤처져서 생긴 착시다.

| 루트 상태 | 실제 |
| --- | --- |
| `M .gitignore` | 변경 내용(`.claude/*` + `!.claude/commands/`, `feedback-shots/`)이 **main의 `.gitignore`에 이미 존재** |
| `D node_modules` | main이 추적 심볼릭링크를 제거함(`a0343d9` "Stop tracking a node_modules symlink", `24f61a5` "Exclude a node_modules symlink, not just the directory"). 루트에는 실제 디렉터리가 있다 |
| `?? .claude/` | main의 `.gitignore`가 `.claude/*`로 무시. 정상 |

**결론**: 루트를 main으로 동기화하면 자동 해소된다. 별도 커밋·되돌리기를 하지 않았다.
루트의 detached HEAD는 이전부터의 상태이므로 이번 계약에서 변경하지 않는다.

## 5. 계약 수정 — BE-LINT 게이트 (중요)

작업서 2절의 `BE-LINT` 별칭은 `ruff check .` / `ruff format --check .`를 **전체 경로**에 대해 실행한다.
기준선이 36 errors + 122개 미포맷 파일이므로, **이 게이트는 우리 변경과 무관하게 즉시 실패한다.**

전체를 고치는 것은 이번 계약 범위가 아니다(피드백 7건 대응). 따라서 게이트를 **변경분 기준**으로 바꾼다:

```
BE-LINT (수정) — 이번 Phase가 건드린 .py 파일에 대해서만:
  ./venv/bin/ruff check <changed.py ...>
  ./venv/bin/ruff format --check <changed.py ...>
```

- 신규·수정 파일은 ruff 기본 규칙을 **통과해야 한다**.
- 손대지 않은 파일의 기존 36건/122건은 **기준선으로 분리 보고**하며 이번 계약에서 고치지 않는다.
- 기준선 수치가 늘어나면 회귀로 간주한다.

`ruff format`을 전체 적용하는 것은 122개 파일을 건드려 모든 후속 diff와 blame을 오염시키므로
**별도 계약으로 분리할 사안**이다. 이번 계약에서 수행하지 않는다.
