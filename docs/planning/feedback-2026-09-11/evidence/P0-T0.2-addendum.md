# P0-T0.2 추가 검증 — CSS 토큰이 실제 브라우저에서 읽히는가

- 작성: orchestrator, 2026-09-11 (P2 진행 중 발견 → 소급 검증)
- 대상: P0-T0.2 `c416841` (이미 main `14eee7d`로 통합됨)

## 왜 추가 검증했는가

P0-T0.2 담당 전문가의 완료 보고에 이런 언급이 있었다:

> this repo's own `vitest.config.ts` runs with `css:false`, so tests always hit the fallback path

즉 **단위 테스트는 항상 폴백 HEX 경로만 탄다.** `getComputedStyle`로 CSS 커스텀 프로퍼티를 읽는
실제 경로는 spy 테스트로 "호출된다"는 것만 확인됐을 뿐, **읽은 값이 유효한지는 검증된 적이 없었다.**

폴백 값이 토큰 값과 동일하므로 **지금은 무해하다.** 그러나 P6-S2-T1(브랜드 팔레트 적용)은
`index.css`의 토큰 값을 바꿔 차트까지 반영되기를 기대한다. 토큰 읽기가 실패하면 폴백이 이겨
**UI 색은 바뀌는데 차트 색만 조용히 그대로 남는다.** P6에서 발견하면 원인 추적이 어렵다.

## 검증 1 — 빌드 산출물에 토큰이 나오는가

`snp-analyzer/app/static-react/assets/index-*.css`:

```
:root,:host{ … --color-plot-grid:#e5e7eb; --color-surface:#fff; … }
body.dark{ … --color-plot-grid:#2d3040; --color-plot-legend-bg:#1a1d27cc; … }
```

Tailwind v4의 `@theme` 블록이 `:root,:host`로, `body.dark`가 그대로 출력된다. 커스텀 프로퍼티는 상속되므로
`document.body`에서 읽힌다.

## 검증 2 — 실제 브라우저 (Chromium)

빌드된 앱을 격리 서버(포트 8114)로 띄우고 Playwright로 `getComputedStyle(document.body).getPropertyValue(...)` 실행:

| 토큰 | 라이트 | 다크 |
| --- | --- | --- |
| `--color-surface` | `#fff` | `#1a1d27` |
| `--color-plot-grid` | `#e5e7eb` | `#2d3040` |
| `--color-plot-legend-bg` | `#fffc` | `#1a1d27cc` |
| `--color-plot-marker-line` | `#fff` | `#2d3040` |

- 값이 **비어 있지 않고**, 라이트/다크가 **서로 다르다**. 토큰 읽기 경로는 런타임에 정상 동작한다.
- 따라서 **P6-S2-T1의 팔레트 교체가 실제로 차트에 반영된다.**

## 관찰: rgba가 8자리 HEX로 최소화됨

`index.css`에 `rgba(255,255,255,0.8)`로 쓴 값이 빌드 후 `#fffc`가 된다 (Lightning CSS 최소화).
색상값으로 동등하며 Plotly는 `#RRGGBBAA` 형식을 파싱한다. 기능적 차이는 없다.
단, 토큰 값을 문자열로 비교하는 테스트를 쓴다면 빌드 전/후 표기가 다를 수 있음을 유의한다.

## 남은 한계

라이트/다크 **차트의 실제 렌더 색을 픽셀 단위로 비교하지는 않았다.** 토큰이 올바른 값으로
읽힌다는 것까지 확인했고, 그 값을 Plotly에 넘기는 코드 경로는 리팩터링 전후 동일하다.
P6-S2-T1에서 팔레트를 실제로 바꿀 때 라이트/다크 차트 시각 확인을 수용 기준에 포함할 것.
