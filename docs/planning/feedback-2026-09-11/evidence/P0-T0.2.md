## 3. 구현 내용

### 3-1. `src/lib/plotly-theme.ts`

- `plotlyColors()`가 이제 `getComputedStyle(document.body).getPropertyValue('--color-…')`로
  색을 읽는다. 반환 키(`paper_bgcolor`, `plot_bgcolor`, `fontColor`, `gridColor`, `lineColor`,
  `legendBg`, `markerLineColor`, `selectedLineColor`)와 함수 시그니처는 그대로다.
- `paper_bgcolor`/`plot_bgcolor` → `--color-surface`, `fontColor` → `--color-text` (기존
  토큰 재사용, 라이트/다크 값이 원래 hardcoded 값과 정확히 일치함을 확인 후 매핑).
- `gridColor`/`lineColor`/`legendBg`/`markerLineColor`/`selectedLineColor`는 기존 토큰과
  값이 정확히 일치하지 않아(예: 라이트 모드 `gridColor` `#e5e7eb` ≠ `--color-border`
  `#e0e4e8`) **새 토큰**을 추가했다: `--color-plot-grid`, `--color-plot-legend-bg`,
  `--color-plot-marker-line`, `--color-plot-selected-line`. `@theme`과 `body.dark` 양쪽에
  기존 하드코딩 값 그대로 추가했다.
- **폴백**: `getComputedStyle`이 빈 문자열을 반환하면(이 레포의 vitest 설정이
  `css: false`라 테스트 환경에서 항상 그렇다) 리팩터링 전 하드코딩 값과 **바이트 단위로 동일한**
  `FALLBACK.light` / `FALLBACK.dark` 상수로 대체한다.
- **다크모드 전환 레이스**: `index.css`의 `body { transition: background-color .3s, color .3s }`는
  `background-color`/`color`라는 계산된(computed) 속성만 트랜지션 대상으로 명시한다. CSS
  커스텀 프로퍼티(`--color-*`)는 이 목록에 없으므로 `body.dark` 클래스 토글과 동시에(트랜지션
  없이) 즉시 바뀐다. 즉 `plotlyColors()`가 읽는 값은 애초에 트랜지션 대상이 아니라서 중간값이
  존재하지 않는다 — "전환 완료 후 읽기"가 아니라 "애초에 전환되지 않는 채널만 읽기"로 방어했다.
  이를 `plotly-theme.test.ts`의 `never reads the transitioned background-color/color
  shorthand, only custom properties` 테스트로 고정했다(`getPropertyValue` 스파이로 호출된
  프로퍼티 이름이 전부 `--`로 시작함을 검증).

### 3-2. `src/lib/constants.ts`

- 새 export: `BRAND_HEX`(중복되던 8개 고정 HEX), `PROTOCOL_PHASE_COLORS`,
  `PROTOCOL_AMP_COLORS`, `PROTOCOL_PHASE_FALLBACK` (구 `ProtocolTab.tsx`의
  `PHASE_COLORS`/`AMP_COLORS`/fallback을 그대로 이전).
- `WELL_TYPE_INFO`와 `COLORS`의 중복 필드(`fam`/`primary`/`allele2`/`rox`/`accent`/
  `danger`/`textMuted`, `'Allele 1 Homo'`/`'Allele 2 Homo'`/`Heterozygous`/
  `'Positive Control'`/`Undetermined`)를 `BRAND_HEX` 참조로 교체했다.
- `WELL_TYPE_INFO.NTC`/`Unknown`/`Empty`/`Omit`, `UNASSIGNED_TYPE`, `MARKER_PALETTE`,
  `COLORS.bg`/`surface`/`border`/`text`는 다른 곳과 중복되지 않아 리터럴로 남겼다(§6).
- **주의**: `BRAND_HEX`는 CSS 커스텀 프로퍼티가 **아니다**. 이 값들은 리팩터링 전에 테마와
  무관하게 항상 고정이었다(예: `COLORS.fam`은 다크 모드에서도 `#2563eb`, `--color-fam`의
  다크 값 `#60a5fa`와는 다르다). CSS 변수로 연결하면 테마 반응성이 생겨 **값이 바뀌는** 것이므로
  하지 않았다 — 지시된 "값 자체는 바꾸지 않는다" 제약을 지키기 위한 의도적 설계다.

### 3-3. `src/lib/genotype.ts`

- `import { WELL_TYPE_INFO, UNASSIGNED_TYPE } from './constants'`에 `BRAND_HEX` 추가.
- `BALANCED_LIGHT`/`BALANCED_DARK`/`DIPLOID_COLORS_LIGHT`/`DIPLOID_COLORS_DARK`의 리터럴을
  `BRAND_HEX.green500`/`green400`/`red600`/`blue600` 참조로 교체. 값은 동일.
- 무지개 램프(`RED_ARM_*`, `BLUE_ARM_*`, `OLD_HEXAPLOID_MUD` 등)는 다른 파일과 중복이 없고
  이미 이 파일에 단일 소스로 있었으므로 손대지 않았다.

### 3-4. `src/components/protocol/ProtocolTab.tsx`

- 로컬 `PHASE_COLORS`/`AMP_COLORS` 상수를 삭제하고 `constants.ts`의
  `PROTOCOL_PHASE_COLORS`/`PROTOCOL_AMP_COLORS`/`PROTOCOL_PHASE_FALLBACK`을 import.
  `getPhaseColor()`의 로직(이름 매칭 → Amplification N 정규식 → 폴백)은 그대로다.
- 삭제/색상 배경(`#fee2e2`/`#dc2626`), GOTO 배너(`#fefce8`/`#854d0e`), 스텝 추가/저장 버튼
  배경(`#3b82f6`/`#10b981`)은 `getPhaseColor`와 무관한 별도 용도이고 이 파일 안에서도
  중복이 없어 리터럴로 남겼다(§6).

### 3-5. `src/index.css`

- `@theme`과 `body.dark`에 `--color-plot-grid`, `--color-plot-legend-bg`,
  `--color-plot-marker-line`, `--color-plot-selected-line`을 동일한 라이트/다크 값 쌍으로
  추가. 기존 토큰 값은 전혀 건드리지 않았다. `--color-fam`/`--color-allele2`도 무변경.

## 4. Characterization test (값 고정 안전망)

`constants.ts`/`genotype.ts`/`ProtocolTab.tsx`는 리팩터링 전 값을 고정하는 테스트를 먼저
작성해 통과(리팩터링 전 기준선)시킨 뒤 리팩터링했고, 리팩터링 후에도 동일 테스트가 통과함을
확인했다.

- `src/lib/constants.test.ts` (신규): `WELL_TYPE_INFO`, `UNASSIGNED_TYPE`, `COLORS`,
  `MARKER_PALETTE`, `BRAND_HEX`, `PROTOCOL_PHASE_COLORS`, `PROTOCOL_AMP_COLORS`,
  `PROTOCOL_PHASE_FALLBACK`의 정확한 HEX를 고정.
- `src/lib/genotype.test.ts` (기존, 무수정): 이미 diploid 트리오(`#dc2626`/`#10b981`/
  `#2563eb`)와 짝수 배수체 balanced 클래스(`#10b981`)를 고정하고 있었다 — 리팩터링 후에도
  변경 없이 통과.
- `src/components/protocol/ProtocolTab.test.tsx` (기존 파일에 테스트 1개 추가): 9가지
  phase(`Pre-read`, `Initial Denaturation`, `Post-read`, `Amplification 1~5`, 미매칭
  phase)에 대해 렌더링된 행의 `borderLeft`와 라벨 `color`가 리팩터링 전 리터럴과 정확히
  같은 RGB로 나옴을 검증(jsdom이 인라인 hex를 `rgb(...)`로 정규화하므로 그 값으로 단언).
