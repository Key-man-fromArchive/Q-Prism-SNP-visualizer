# P1-S1-T1 — ASG-linked context label normalization

Branch: `feedback/p1-linked-label` (worktree `worktree/feedback-p1`)
Scope: `snp-analyzer/frontend/src/components/layout/Header.tsx`,
`Header.test.tsx`, `src/locales/en.ts`, `src/locales/ko.ts`. No backend
changes; `linked_context` payload shape is untouched.

## Problem

The header rendered the raw ASG linkage identifiers `context.target_type`
and `context.target_id` (e.g. `ad_hoc` / `1`) next to the product name in
both render paths (`xl:` desktop row and the `<details>` disclosure used
below `xl`). These are internal ASG plumbing values with no meaning to the
operator. The human-readable name ASG actually sends (`tag_alias` when set,
otherwise `marker_id`) was rendered *in addition to* the raw pair rather
than instead of it.

## RED — failing tests first

Added a `describe('ASG linked context label', ...)` block to
`Header.test.tsx` with 4 cases before touching `Header.tsx`:

1. `ad_hoc` with `tag_alias: ''`, `marker_id: 'Ad hoc SNP Analyze'` → only
   `Ad hoc SNP Analyze` should render; raw `ad_hoc` / `RAWID1` must not
   appear anywhere (text or `title`/`aria-label`).
2. `tag_alias` present alongside `marker_id` → `tag_alias` wins, raw
   `target_type`/`target_id` still hidden.
3. Unknown `target_type` (`MYSTERY_TYPE`) with no `tag_alias`/`marker_id` →
   must not crash, must not leak the raw type/id, and must still render a
   non-empty neutral label (block is not suppressed).
4. `linkedContext` entirely absent → `.header-linked-context` does not
   render at all.

## GREEN — implementation

`Header.tsx`:

- Added `resolveLinkedLabel(context, t)`: returns `tag_alias` if it is a
  non-empty string, else `marker_id` if it is a non-empty string, else
  `t.asgTargetLabel(context.target_type)` (which itself always resolves to
  either a mapped or neutral string — never the raw value).
- `LinkedIdentity` no longer takes the whole `context`; it now takes the
  already-resolved `label` and renders exactly one `<span className="badge">`.
  This is the single presentation primitive used by **both** render paths.
- `HeaderLinkedContext` computes `label` once via `resolveLinkedLabel` and:
  - returns `null` (no block at all) if the label is empty,
  - uses `label` (not raw `target_type`) in the collapsed `<summary>` text,
  - passes `label` to `LinkedIdentity` in both the `<details>` branch (below
    `xl`) and the always-flex desktop branch (`xl:flex`).
- Raw `target_type`/`target_id` are no longer referenced anywhere in the
  render output, including `title`/`aria-label` attributes.

`src/locales/en.ts` / `src/locales/ko.ts` — added, in both files
simultaneously (the `Translations` type is derived from `en`, so `ko.ts`
would fail to typecheck if only one were updated):

```ts
asgTargetLabel: (targetType: string) => ({
  ad_hoc: 'Ad hoc analysis',        // 애드혹 분석
  marker_version: 'Marker version', // 마커 버전
  design_run_item: 'Design run item', // 디자인 실행 항목
} as Record<string, string>)[targetType] ?? 'ASG linked', // ko: 'ASG 연동'
```

Only the three `target_type` values actually observed in the repository
(`snp-analyzer/tests/test_asg_launch_auth.py:56,87`,
`snp-analyzer/tests/test_asg_result_save.py:105,209,302`) are mapped.
Anything else (present or future) falls back to the neutral
`'ASG linked'` / `'ASG 연동'` string rather than guessing or leaking the
raw value.

## Both render paths verified

Both the `xl:hidden` `<details>`/`<summary>` disclosure and the
`hidden xl:flex` desktop row call the same `LinkedIdentity` with the same
`label`, and the `<summary>` text itself was switched from
`` `ASG · ${context.target_type}` `` to `` `ASG · ${label}` ``. The existing
test `keeps full linked identities in a keyboard disclosure...` (which sets
a long `tag_alias`) continues to assert the alias appears exactly twice —
once per render path — confirming neither path was missed.

## D-8 — unresolved

The full enumeration of ASG `target_type` values is not confirmed by any
ASG contract document available in this repository — only the three
values actually exercised by `snp-analyzer/tests/test_asg_launch_auth.py`
and `test_asg_result_save.py` are mapped here. `marker`, `design_result`,
`order_item`, and any other `target_type` ASG may send are **not** in the
mapping table and will render the neutral `'ASG linked'` / `'ASG 연동'`
fallback. If ASG's actual contract turns out to include additional
`target_type` values, they should be added to `asgTargetLabel` in both
locale files once confirmed — this task deliberately does not guess them.
