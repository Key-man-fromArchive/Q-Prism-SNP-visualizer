## GREEN — implementation

### Tab IA (`TabNavigation.tsx`, `navigation-store.ts`)

`navigationTabs`/`NavigationTab` (navigation-store.ts) and `TabId`
(TabNavigation.tsx) are now the *same* union — `TabId` is a type alias for
`NavigationTab` imported from the store, so the two can never drift apart
again the way `analysis`/`protocol` vs `TabId` had. New order matches the
target IA exactly: `plate, rawdata, results, quality, statistics, compare,
library, project` as primary tabs, with `settings, references, users,
feedback` in the "More" overflow menu (Settings newly demoted — P4 moves
normalization/axis controls onto the plot header, so it stops needing a
primary slot). The roving-tabindex fallback that anchored focus to a fixed
`'analysis'` id when the active tab is in overflow now anchors to
`primary[0]?.id` instead, so it doesn't silently break the next time the
first tab's id changes.

### `WorkspaceTabs` absorption (`AnalysisWorkspace.tsx`)

The inner `role="tablist"` + `WorkspaceTabs` (Plate Setup | Analysis
sub-tabs) is deleted outright. `AnalysisWorkspace`'s two surface panels now
carry `id="main-panel-plate"` / `id="main-panel-results"` and
`aria-labelledby="tab-plate"` / `"tab-results"` directly (`data-testid`
values — `workspace-panel-plate` / `workspace-panel-analysis` — are
unchanged, per the task's explicit e2e-selector scope). The "split into
markers" banner CTA, which used to call `setSurface('plate')` directly, now
calls `setTab('plate')` — necessary because `setSurface` alone would move
the visible content to Plate Setup while leaving the top-level tab bar
still highlighting "Results", an inconsistent state that could only exist
because the two-tier tab design no longer exists. `bannerDismissed` state
and the session-reset-on-change logic are unchanged, per the task
instruction that P4 replaces them with a scope selector later.

### `surface`: kept, made tab-derived going forward

Per the orchestrator's own recommendation, `WorkspaceSurface` (`'plate' |
'analysis'`) is untouched — it is still read by `quality-target.ts`
(`ResolvedQualityTarget.surface`), `quality-navigation.ts`, and
`workspace-history.ts`'s discrete-change diffing, none of which needed
edits. What changed is *who writes it*: `setTab` (used by the real
TabNavigation clicks) now derives `surface` as a side effect —
`tab==='plate' → surface:'plate'`, `tab==='results' → surface:'analysis'`,
any other tab leaves `surface` untouched (so a return-from-quality/history
restore still knows which of the two surfaces to come back to). `setSurface`
itself still exists and is unchanged (still used by
`quality-navigation.ts`'s `finishReturn`/`apply`, and by the URL
`?surface=` round-trip in `parseNavigation`, both untouched).

### The `'analysis'` legacy value, and why it still exists

`quality-navigation.ts` (forbidden — P3-S2-T1 owns it) unconditionally
writes `useNavigationStore.setState({ tab: 'analysis', surface, ... })`
when routing to a quality target. Removing `'analysis'` from
`NavigationTab` outright would have been a type error in that
forbidden file (which cannot be edited under this task), **and** would have
broken type-checking or the actual assertions in over a dozen *other*
already-passing unit tests elsewhere in the tree that use `tab: 'analysis'`
as a generic "the workspace is open" placeholder
(`App.analysis.test.tsx`, `CycleControl.test.tsx`,
`use-keyboard-assignment.test.ts`, `use-quality-focus.test.tsx`,
`workspace-history.test.ts`, `quality-navigation.test.ts`, etc. — none of
which this task owns or may edit).

The resolution: `NavigationValue.tab`'s type is `NavigationTab |
'analysis'` (an internal `StoredTab` alias, not part of the public
`NavigationTab` union `TabNavigation`/`setTab` use). Two new exported
helpers normalize it everywhere a *decision* is made from it:

- `isWorkspaceTab(tab)` — true for `'plate' | 'results' | 'analysis'`.
  Used by `keyboard-authority.ts` (`keyboardAnalysisReady`, previously a
  stale `nav.tab === 'analysis'` exact match that would have gone false
  the instant a user was on the new `plate`/`results` tabs — a real
  shortcut-disabling regression, not just a test artifact) and
  `use-quality-focus.ts` (same stale check, gating the reveal-and-focus
  effect after a quality-target jump).
- `resolveDisplayTab(tab, surface)` — collapses the legacy `'analysis'`
  value into the surface-appropriate real tab (`plate` if
  `surface==='plate'`, else `results`); never returns `'analysis'`. Used
  once, in `App.tsx`, to compute the `activeTab` that actually drives
  rendering/highlighting, so the top nav never shows a phantom
  unselected state right after a quality-target navigation.

`use-current-analysis-request.ts`'s `surface: 'analysis' | 'settings'`
parameter (called by `AnalysisTab.tsx`/`MultiMarkerAnalysisPanel.tsx` with
`'analysis'`, unchanged) is kept as-is by name but its internal comparison
switched from `state.tab === surface` to `isWorkspaceTab(state.tab)` for the
`'analysis'` case — this restores its pre-P3-S1-T1 meaning ("either
workspace tab is open," which is what let the request registration stay
live across the old Plate Setup/Analysis sub-tab switch) rather than
narrowing it to an exact-match on a tab id that no longer exists.

### `App.tsx` panel mounting

`AnalysisWorkspace` is still mounted exactly once whenever `sessionId`
exists (never twice, never unmounted on tab switch — the CSS-only
`hidden`-class pattern is preserved verbatim, just re-targeted from
`activeTab === "analysis"` to `isWorkspaceTab(activeTab)`). Because
`AnalysisWorkspace` itself now owns `main-panel-plate`/`main-panel-results`
directly, `App.tsx` no longer wraps it in its own `main-panel-*` div — it
only supplies the two now-required hidden placeholder panels
(`main-panel-plate`/`main-panel-results`) for the `!sessionId` case, so
`TabNavigation`'s `aria-controls="main-panel-plate"` /
`"main-panel-results"` always resolves to a real element even before a
session exists (verified by `App.analysis.test.tsx`'s existing generic
aria-controls/aria-labelledby loop, which runs precisely in that
no-session state and needed no changes). The generic per-tab wrapper
(previously skipping `role`/`aria-labelledby` only for `'analysis'` +
`references`/`users`) now skips for `plate`/`results` + `references`/`users`
via a small `ownsSemanticsElsewhere()` helper. `'protocol'` → `'rawdata'`
throughout; the two `setActiveTab("analysis")` call sites (open-session,
"back to workspace" after loading a project) became `setActiveTab("results")`.

### Locales

`tabAnalysis`/`tabProtocol` → `tabPlate` ('Plate Setup'/'플레이트 설정',
reusing the existing wording), `tabRawdata` ('Raw data'/'원시 데이터'),
`tabResults` ('Results'/'결과' — the literal word requested in the
feedback). `wsTabAnalysis` (the old sub-tab label) is now unused dead data
in both locale files but was left in place rather than deleted, since
removing an object property that nothing type-checks against carries no
build/test benefit and the smaller diff seemed preferable; flagging it here
rather than silently leaving it unexplained.

### `keyboard-authority.ts` / `use-quality-focus.ts` / `use-current-analysis-request.ts`

None of these three files were in the task's originally-listed write scope.
They needed to change anyway: all three compared `nav.tab` against the
literal `'analysis'` to decide whether the workspace was "open" for keyboard
shortcuts, quality-target auto-focus, and clustering-request registration
respectively. Left unmodified, all three would have gone *silently* wrong
the moment a real user was on the new `plate`/`results` tabs (shortcuts
disabled, auto-focus not firing, requests not registering) with **no unit
test catching it**, because every existing test for these three files only
ever exercised the default/legacy tab value, never `'plate'`/`'results'`
directly. New coverage was added specifically to close that gap (see RED
section and `keyboard-authority.test.ts`'s new
`it.each(['plate', 'results'])` case).

- **`quality-navigation.ts`'s `tab: 'analysis'` literal.** It still works
  (via `isWorkspaceTab`/`resolveDisplayTab`), but it's writing the
  pre-migration value. P3-S2-T1 should change it to derive the tab from
  `surface` directly (`surface === 'plate' ? 'plate' : 'results'`) so the
  store stops producing the legacy value at all; once that lands, the
  `'analysis'` member of `StoredTab` in `navigation-store.ts` and the two
  `isWorkspaceTab`/`resolveDisplayTab` normalizations can be deleted (they
  were added specifically to tolerate this one remaining writer).
- **Old bookmarked `?tab=analysis`/`?tab=protocol` URLs.** `readSelection`'s
  `tab()` guard already rejects both (they're not in the new
  `navigationTabs` list) and falls back to the session's real default —
  this task deliberately did not add a redirect/alias for the old query
  values, per the task brief's explicit deferral of "구 URL 매핑" to
  P3-S2-T1 (owner of `workspace-location.ts`/`workspace-history.ts`).
- **Feedback `page_key`.** `FeedbackWidget pageKey={activeTab}` in `App.tsx`
  now naturally records `'plate'`/`'rawdata'`/`'results'` instead of
  `'analysis'`/`'protocol'` for newly-submitted feedback — this file and
  `feedback-context.ts` were not touched (both forbidden/adjacent-forbidden
  in this task), so any admin-side display logic that special-cases the old
  string values for **already-stored** feedback items is P3-S2-T1's to
  reconcile.
- **`sessionQueries`** (mentioned in the task brief) — no file in this
  task's diff references it; left entirely to P3-S2-T1 as instructed.
