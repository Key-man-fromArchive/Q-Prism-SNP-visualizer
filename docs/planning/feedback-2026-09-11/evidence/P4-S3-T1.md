## GREEN — implementation, per FB-03 §3 block

### 1. Warning demotion respects severity (§3-1, §8)

`AnalysisTab.tsx` now computes `gradedAnalysisWarnings(analysisWarnings, t)`
(from P4-R1-T1's `lib/analysis-warnings.ts`, **unmodified**) and splits it
into `blockingWarnings`/`advisoryWarnings`:
- `blockingWarnings` render in the **same position** as before (the
  `analysis-warnings` Callout, above `WellSelectionToolbar`/`analysis-grid`)
  — nothing moved for them.
- `advisoryWarnings` render in a **new** `analysis-warnings-advisory` Callout
  directly below `ResultsTable`, before `AmplificationOverlay`.
- Both are wrapped in a `tabIndex={-1}` div carrying `aria-live` (`assertive`
  for blocking, `polite` for advisory) so they stay in the accessibility
  tree and are announced as they arrive, whichever tier they land in.
- The sticky toolbar gained an `analysis-warnings-badge` button
  (`⚠ N warning(s)`, only rendered when `gradedWarnings.length > 0`) that
  focuses + `scrollIntoView`s the advisory block if one exists, else the
  blocking block — useful since the sticky toolbar can otherwise scroll the
  blocking Callout out of view.

**No severity was changed.** `analysisWarningSeverity`/`WARNING_SEVERITY`
in `lib/analysis-warnings.ts` were not touched — all three real backend
codes (`relative_ntc`, `low_n`, `anchor_conflict`) are still `blocking` and
still render above the fold today. The advisory path is exercised in tests
via a **mocked** `gradedAnalysisWarnings` (a synthetic `advisory_code`),
since no real code currently grades that way by policy — this is the
mechanism FB-03 §8 asked to be built ahead of any future advisory code,
not a change to today's grading.

### 2. Context summary collapsed (§3-1)

`AnalysisWorkspace.tsx`'s `analysis-context-summary` is now a `<details>`
(closed by default, no `open` attribute) whose `<summary>` is a one-line
`analysisContextSummaryLine(cycle, totalCycles, wells, markerCount)`
(e.g. "Cycle 40/40 · 96 wells · no marker split"). The previous
`AnalysisResultStatus`/`PlateScopeSummary` pair is unchanged in content, now
nested inside an `analysis-context-summary-body` wrapper (CSS grid target
moved from `.analysis-context-summary` to `.analysis-context-summary-body`
so `<summary>` isn't forced into the two-column grid alongside them).

### 3. Group presets conditional (§3-2)

`WellSelectionToolbar.tsx` now computes `showGroupPresets = hasSelection ||
manualNames.length > 0` and only renders the `manual-group-presets` block
(the six `Group N` buttons plus any extra manual names) under that
condition. The **"+ Add group" trigger always remains** — it is the only
path to creating the first manual group, and clicking it with nothing
selected still surfaces the existing `manualGroupSelectFirst` inline error
(unchanged behavior, just no longer preceded by six dead buttons).

### 4. Guidance text relocated (§3-2)

The former `t.selectionHelp` span (always-on, full width, inside
`WellSelectionToolbar`) was removed from there and now renders as a
`plate-view-hint` paragraph directly above `<PlateView />`, gated on
`selectedWells.length === 0`, in **both** call sites that mount `PlateView`
next to `WellSelectionToolbar`: `AnalysisTab.tsx` (whole-plate view) and
`MultiMarkerAnalysisPanel.tsx` (per-marker view) — `PlateView.tsx` itself
was not touched.

### 5. Scope selector replaces the split-marker banner (§3-3)

`AnalysisWorkspace.tsx`'s `single-marker-analysis-view` branch now renders
an always-present `analysis-scope-selector` (`role="group"`) with a
`scope-whole-plate` pill (current state) and a `scope-split-marker-cta`
button (`setTab("plate")`, reusing `t.wsSplitBannerCta`) in place of the old
dismissible `split-marker-banner`. Once `markers.length > 0`,
`MultiMarkerAnalysisPanel`'s own `marker-selector-sidebar`/
`marker-selector-dropdown` occupies the same visual slot, unchanged.

**`bannerDismissed` and its session-transition reset are fully removed** —
the `useState(false)` for it, the `prevSessionId` render-phase reset effect
that re-armed it per session, and the dismiss button (`split-marker-dismiss`,
its `X` icon import) are all gone; nothing references `bannerDismissed`
anymore (verified with `grep -rn bannerDismissed src/` returning nothing).
The now-unused `wsSplitBannerText`/`wsSplitBannerDismiss` locale strings were
removed from both `en.ts`/`ko.ts`; `wsSplitBannerCta` is kept and reused for
the new CTA's label.

### 6. `ResultsTable` promoted (§3-4)

`index.css`'s `[data-testid="results-scroll-region"] { max-height: 24rem;
overflow-y: auto; }` is now scoped to `@media (max-width: 1279px)` — the
same breakpoint boundary the two-column `.analysis-grid` already uses.
At >=1280px (including the reported 1920x911 case) the results region grows
to its natural height as a first-class area instead of clipping genotype
calls to a 24rem scroll well below the fold. Below 1280px the existing
internal-scroll behavior is unchanged (this is deliberately narrower than a
blanket removal, to avoid silently changing the 390x500 mobile 384-well
layout that `tests/24-responsive.spec.ts` already asserts scrolls
internally — see "Known follow-up" below).
