Branch: `feedback/p6-brand` (worktree `worktree/feedback-p6`), built on top of

## Problem

> "이 화면은 SNP analysis. Qprism 플랫폼의 SNP 판별을 담당하는 중요한 기능입니다.
> 미적으로 매우 뒤떨어지는 상황입니다. Q-Prism 로고, Invirustech 로고, Q-Prism art
> 같은게 들어가면 좋겠어요" (FB 2026-09-11, `0de8fb3361884951`)

The upload screen (the empty-session landing screen) had no favicon, no
logo, and no brand art — just the bare drop zone. The brand kit already
existed in `public/` (imported by earlier tasks); this task wires it in.

## What was built

### 1. Favicon (`index.html`)

Added the two links that were completely missing:

```html
<link rel="icon" type="image/png" sizes="32x32" href="/favicon-32.png" />
<link rel="apple-touch-icon" sizes="180x180" href="/apple-touch-icon-180.png" />
```

Locked by `src/index.html.test.ts` (new), which reads the raw HTML file and
regex-matches both `<link>` tags — mirrors the existing pattern in
`src/index.css.test.ts` (raw-file assertions), rather than an unwritten
convention.

### 2. Upload-screen hero (`UploadZone.tsx`)

Rendered only when there is **no session** (`!sessionId`, read from
`useSessionStore` inside `UploadZone` itself — not only relying on
`App.tsx`'s `visibility.upload` gate, because `UploadZone` is also rendered
standalone in its own test suite and the task explicitly required a test
proving "세션이 없을 때만 히어로가 렌더된다"):

```
┌──────────────────────────────────────────────┐
│ [white chip: Q-prism wide logo]   [hero art]  │
│ SNP discrimination · allele-specific          │  ← t.heroSubtitle
│ clustering                                     │
│ Decode the Cue, Reveal the Spectrum (italic)  │  ← t.heroTagline
├──────────────────────────────────────────────┤
│              (existing drop zone — unchanged)  │
├──────────────────────────────────────────────┤
│         (inline FileWorkspaceTrigger — P5)     │
│              (RecentSessions — unchanged)      │
│                 ...templates, guide...         │
│         [Invirustech logo] Powered by ...      │  ← footer
└──────────────────────────────────────────────┘
```

- **Logo**: `<picture>` with `qprism-wide.webp` (primary) and
  `qprism-wide.png` (fallback), `alt={t.appTitle}` ("Q-prism® Cluster
  Caller" — a real, meaningful description, not empty/decorative).
  `loading="lazy"`, native `width`/`height` set to the asset's real pixels
  (660×178) so the browser can reserve space and preserve aspect ratio
  while Tailwind (`h-9 sm:h-10 w-auto`) controls the rendered size.
- **Product-name duplication (the flagged known inconsistency)**: the logo
  image already renders `Q-Prism®` (capital P) as part of its own artwork,
  while the app text everywhere else uses `Q-prism®` (lowercase p, per the
  brand doc). Per the assignment's explicit guidance, the hero does **not**
  put the product name text next to the logo at all — only a functional
  descriptor (`t.heroSubtitle`) and the brand tagline (`t.heroTagline`) sit
  under it, so the two different capitalizations never appear adjacent to
  each other on screen. `alt={t.appTitle}` still uses the correct
  lowercase-p text (accessibility text is not visual rendering, so this
  doesn't reintroduce the visible clash).
- **Hero art (`qprism-hero.jpg`) — used, not skipped**: the source asset is
  a 1055×1491 portrait photo (a physical prism splitting light — directly
  on-brand with the "Prism" identity in
  `docs/planning/feedback-2026-09-11/brand-identity-reference.md`).
  Used as a small bounded decorative card (`w-24 h-32` → `md:w-28 md:h-36`,
  `object-cover`, rounded, bordered), **not** full-bleed/full-height —
  this keeps the hero's total height fixed regardless of the source
  image's tall aspect ratio, so the upload screen is not taller than
  before. `alt=""` + `aria-hidden="true"` (purely decorative — the logo
  and text already carry the meaning), `loading="lazy"`. **Hidden below
  the `sm` breakpoint** (`hidden sm:block`) — at 400px width it does not
  render at all, so there is nothing to break or to make the page taller
  on the width explicitly called out for verification (see 400px
  screenshot below: the card is simply absent, logo/text stack alone).
- **Dark-mode logo readability**: `qprism-wide.png`/`.webp` is a dark-navy
  wordmark on a **transparent** background. Verified visually against
  `body.dark`'s near-black `--color-bg` (`#0e1413`) — the dark text would
  be near-invisible directly on that background. Fixed with the
  background-chip approach the assignment itself suggested: the logo sits
  inside `inline-flex rounded-lg bg-white px-3 py-2 shadow-sm`, an explicit
  light chip independent of the app's `--color-*` theme tokens, so it
  reads identically (and correctly) in both light and dark mode without
  any `filter`/invert that would distort the multicolor triangle mark. The
  same chip technique (`bg-white` + `rounded`) is applied to the small
  Invirustech mark in the footer for the same reason (its "tech" wordmark
  is a light gray, also low-contrast on `--color-bg` dark). Confirmed live
  in `p6-s3-t1-dark.png` below — logo and footer mark both clearly legible.
- Project uses no Tailwind `dark:` variant (`grep -rn "dark:" src` found
  none outside two unrelated string props); dark mode is entirely
  `body.dark` + CSS custom properties, confirmed in `src/index.css`. The
  white chip is theme-independent by construction, so it needed no
  `dark:`-variant styling to "flip" between modes.

### 3. "Powered by Invirustech" relocation

- **Header.tsx**: the existing external link is now gated on `sessionId` —
  shown while a session is active (unchanged position/behavior), hidden
  while there is none (moved to the footer below instead). One-line
  change; no other Header behavior touched.
- **UploadZone.tsx footer**: same link (same `href`, `target`, `rel`,
  same `t.poweredBy` text), now paired with the `invirustech.png` mark
  (`alt=""` + `aria-hidden`, decorative — the text already says
  "Powered by Invirustech") inside the same white chip treatment, centered
  at the bottom of the upload screen, only rendered while `!sessionId`
  (same guard as the hero, for the same reason).

### 4. Locale keys added (`en.ts` / `ko.ts`)

| `heroSubtitle` | `SNP discrimination · allele-specific clustering` | `SNP 판별 · 대립유전자 클러스터링` |
| `heroTagline` | `Decode the Cue, Reveal the Spectrum` | `SNP의 비밀을 밝히다` |

Both pulled directly from
`docs/planning/feedback-2026-09-11/brand-identity-reference.md`'s
"Taglines" table (main + Korean) plus the mockup's own functional line, not

a missing key there is a compile error, not a silent gap — `tsc --noEmit`
passing confirms both files stayed in sync.
