## 1. 배경과 문서의 역할

2026-09-07 UI/UX 리뷰에서 분석 결과의 표시, 내보내기, 키보드 조작, 반응형과 작업 복원에 문제가 확인됐다. 공통 버튼·모달·메뉴와 라이브러리, 단일/마커별 분석 구조는 이미 존재한다. 이번 개선은 이 기반을 재사용하면서 사용자가 결과를 신뢰하고 작업을 이어갈 수 있도록 만드는 데 집중한다.

이 문서는 이번 개선 범위에서 아래 변경표의 기준을 우선 적용한다. 나머지 기존 요구사항은 유지하며, 기존 작업의 완료를 선언하지 않는다. 작성 자체가 코드 변경이나 배포를 의미하지 않는다. 공통 컴포넌트·테스트 도구의 신규 도입 등 과거 전제는 현재 코드와 대조해 중복 작업을 피한다.

## 2. 검증 근거와 한계

임시 DB와 합성 2배체 예제로 로컬 인증, 업로드 홈, 단일 분석, 플레이트 설정, 마커별 분석, 프로토콜·설정·품질·통계·비교·라이브러리·프로젝트·참고문헌·관리 화면의 주요 화면을 탐색했다. 분석 화면은 1440·1280·1024·768·390px 및 라이트/다크에서 확인했다. 프리셋 저장 실패는 브라우저에서 HTTP 500 응답을 주입해 확인했다.

모든 화면의 전체 작업 경로를 검증한 것은 아니다. ASG 연동 저장, 실제 장비 파일별 가져오기 전체 경로, PDF/XLSX 내용 정확성, 384웰 데이터, 보조공학 도구 사용성은 추가 검증 대상이다. 아래의 관찰 결과와 새롭게 제안하는 요구사항을 구분한다.

후속 교차 리뷰에서는 PDF/XLSX의 사이클 선택 코드와 저장 계약을 추가 확인했다. 이는 보고서 파일의 내용·렌더링을 실측 검증했다는 의미는 아니다. 서버 시작 시 DB에서 세션·판정을 복원하는 경로가 있으므로, 브라우저 위치 유실을 서버 데이터 소실로 취급하지 않는다.

## 3. 목표와 범위

### 목표

1. 화면과 내보낸 결과가 같은 분석 조건을 가리키도록 한다.
2. 정상·경고·확인 불가를 구분하고, 문제 확인에서 해당 웰 검토까지 연결한다.
3. 키보드, 좁은 화면, 새로고침 상황에서도 작업을 이어갈 수 있게 한다.
4. 분석에 필요한 결과와 선택 웰 정보를 가까이 배치하고 상세 조작은 필요할 때 펼친다.

### 포함 범위

- QC 응답 확장, 분석 조건 저장, CSV·PNG·PDF·XLSX의 조건 일치와 범위 표시.
- 헤더·탭·단일/마커별 분석·플레이트 설정의 배치와 상호작용.
- 프리셋·최근 세션의 실패 안내, 작업 위치 복원, 품질 화면의 웰 이동.
- 한국어/영어 문구, 키보드 접근성, 테마별 판별 단서.
- 수동 웰 유형 변경의 실행취소 연결과 업로드 실패 내역 유지.

### 제외 범위

- 신규 판정 알고리즘, QC 임계값 변경, 생물학적 유효성 검증.
- 신규 장비 파서, 신규 보고서 형식, 인증·권한 정책 변경.
- 전체 화면을 강제 단계형 마법사로 전환하거나 최상위 정보구조를 전면 교체하는 작업.
- 모바일에서 데스크톱과 동일한 분석 밀도나 터치 드래그 편집을 보장하는 작업.
- 과거 분석 버전 탐색, 임의 시점 되돌리기, 파일 자동 재시도·영속 업로드 큐.

## 4. 사용자 흐름

주 사용자는 장비 데이터를 업로드하고 판정 결과를 검토·보정·공유하는 실험 담당자다. 재방문 시에는 기존 실행을 다시 열어 검토를 이어간다.

1. 파일 업로드 또는 최근 실행 열기. 실패 시 원인과 재시도를 같은 위치에서 제공한다.
2. 기본 전체 플레이트 분석을 확인한다. 필요할 때 플레이트 설정에서 마커를 배정한다.
3. 현재 마커·사이클·정규화·배경 차감 조건을 확인하고 결과를 검토한다.
4. 경고를 열어 원인과 대상 웰을 확인하고, 해당 웰 상세로 이동한다.
5. 현재 보기와 마지막 분석 조건이 다르면 재분석하거나 내보낼 조건을 명시적으로 선택한다.
6. 결과를 내보낸다. 새로고침 후에는 접근 권한을 재확인하고 같은 작업 위치를 복원한다.

## 5. 기능 요구사항과 수용 기준

우선순위는 P1=결과 신뢰성과 핵심 조작, P2=작업 연속성과 화면 사용성으로 정의한다. 기존 문서의 P0/P1/P2와 별도의 후속 작업 우선순위다.

### UX-01. QC 상태와 적용 범위 일치 — P1 / F01·F13

기존 `ok/wells`는 호환성을 위해 유지하되, `ntc_check.status`를 `ok | warning | no_ntc | insufficient`로 추가한다. 각 NTC 웰에는 `flagged: boolean | null`과 구조화된 사유 코드를 추가한다. `null`은 평가 불가이며 정상으로 표시하지 않는다. 경고 문장을 파싱해 오염 웰을 추정하지 않는다. 신규 응답 필드가 없는 서버는 `ok/wells`로 보수적으로 표시하되, 웰별 오염 여부가 불명확하면 이를 명시한다.

| 입력/평가 결과 | 사용자 표시 | 상세 및 행동 |
| --- | --- | --- |
| 요청 중 | QC 확인 중 | 이전 값은 갱신 중으로 구분 |
| NTC 1개 이상, 모두 평가 가능, 경고 없음 | 정상 | 적용 사이클·조건과 검사한 NTC 수 |
| 평가된 NTC 중 경고 있음 | 오염 의심 | `flagged=true` 웰과 사유. 평가 불가 웰이 있으면 별도 안내 |
| NTC 0개 (`ok=true, wells=[]` 포함) | NTC 없음 — 확인 불가 | NTC 지정/실험 구성 확인 안내 |
| NTC는 있으나 평가 근거 부족, 경고 없음 | 측정 불충분 | 누락/불충분 사유. 임계값 변경으로 해결하지 않음 |
| 요청 실패·응답 계약 오류 | QC 확인 실패 | 재시도. 정상/오염 여부 단정 금지 |

- 현재 알고리즘의 임계값은 유지한다. NTC 개수·유효 신호·기준 신호의 존재 여부로 평가 가능성을 명시한다.
- 사이클 추천의 `ntc_onset_cycle`은 NTC 상승 감지 시점이며 QC 오염 판정과 별개다. 정상적인 검출 평가 후 미검출이면 “NTC 상승 미검출”, 평가하지 못했으면 “NTC 상승 평가 불가”로 표시한다. 추천 API에도 평가 상태·사유를 추가하며, `null`만으로 “오염 없음”이라고 표시하지 않는다.
- `authoritative === 'markers'`일 때 풀링된 플레이트 분리도를 숨기고 선택 마커의 콜률·분리도를 이름과 함께 표시한다. 마커 선택이 없는 화면은 마커별 요약을 제공한다. 플레이트 NTC 검사는 “플레이트 전체”로 구분하고 마커별 값인 것처럼 표시하지 않는다.
- 판정 기반 콜률·분리도는 UX-02의 저장 조건과 결과 버전을 사용한다. 현재 보기와 다르면 마지막 분석 조건이라고 표시한다. 현재 사이클의 NTC 검사는 별도 조건 라벨을 가진다.
- 수용 기준: 위 상태표, 정상/오염 NTC 혼합, 서로 다른 배수성의 두 마커, 지연 응답을 검증한다. 오래된 응답은 최신 세션·조건을 덮어쓰지 않으며, 상이한 지표는 의미와 적용 조건으로 구분된다.

### UX-02. 분석 조건 계약과 내보내기 일치 — P1 / F02·F03·F11·F12

#### A. 저장 계약과 상태 소유권

서버의 최신 완료 결과를 판정 조건의 기준으로 삼는다. `ClusteringResult`와 DB 직렬화, 조회 API에 아래 `analysis_context`를 추가한다. 클라이언트의 새 `analysis-store`는 서버 응답과 요청 상태를 관리하며, 현재 보기는 기존 선택·설정 스토어에서 파생한다.

| 필드 | 저장 의미 |
| --- | --- |
| `schema_version`, `result_revision`, `analysed_at` | 계약 버전, 서버 발급 결과 식별자, UTC 완료 시각 |
| `cycle`, `use_rox`, `normalization_applied`, `background` | 실제 계산 사이클, 정규화 요청과 실제 적용 여부, 배경 차감 |
| `algorithm`, `parameters` | 배수성·클러스터 수·임계값·수동 경계 등 실제 계산에 사용한 전체 매개변수 |
| `regions` | 마커 ID·웰 배정·배수성·마커별 실제 매개변수의 스냅샷 |
| `input_revision` | 데이터·마커 배정·수동 웰 유형 등 결과에 영향을 주는 입력의 서버 관리 버전 |

- 컨텍스트와 판정·신뢰도는 함께 저장한다. 조회한 조건을 현재 설정으로 추정해 채우지 않는다. 컨텍스트 없는 기존 결과는 `legacy_unknown`으로 읽고 재분석을 안내한다. 기존 결과 열람은 허용하되 검증된 조건의 보고서로 내보내지 않는다.
- 현재 보기와 저장 조건의 차이, 입력 변경, 요청 중 상태를 구분한다. 사이클·정규화·배경·알고리즘·임계값·배수성 변경은 불일치 사유다. 마커 배정·수동 유형 변경은 입력 버전을 바꾼다. 단순 마커 선택·축 범위·언어 변경은 판정 변경이 아니다.
- 최신 완료 결과 한 건을 유지하며 과거 이력 조회는 제공하지 않는다. 내보내기는 `result_revision`을 지정하고 서버가 조건·입력 버전을 확인한다. 결과 교체나 입력 변경으로 일치하지 않으면 409와 재시도 안내를 반환한다. 요청이 수락되면 동일 스냅샷으로 파일을 완성한다.
- 새 필드는 기존 조회 응답과 호환되도록 추가한다. 내보내기에서 버전 생략 시에도 서버는 최신 결과의 조건을 검증한다. 다른 조건의 좌표와 판정을 섞는 기존 요청은 명시적 오류로 전환하고 연결 소비자·테스트를 함께 갱신한다.

#### B. 단일/마커별 분석의 실행 정책

- 단일 분석은 현재의 명시적 실행 정책을 유지한다. 최초 업로드에 저장 결과가 없을 때만 기존 자동 분석을 허용한다.
- 마커별 분석은 기존의 입력 안정화 후 자동 재분석을 유지한다. 재생 중에는 중지하며, 자동 계산 중/완료/실패와 적용 사이클을 표시한다. 복원 중에는 자동 실행하지 않는다(UX-06).
- “현재 사이클로 재분석”과 “추천 사이클로 분석”을 구분한다. 현재 버튼의 추천 사이클 선택 동작을 재분석 경로에 무조건 재사용하지 않는다. 내보내기에서 현재 조건 재분석을 선택하면 사이클을 바꾸지 않는다.
- 계산 중에는 판정 포함 내보내기를 막는다. 늦은 응답뿐 아니라 서버의 오래된 작업 완료도 최신 결과를 덮어쓰지 않도록 입력 버전·요청 순서를 검증한다. 실패 시 이전 결과를 현재 결과처럼 표시하지 않는다.

#### C. 형식별 범위와 조건 선택

| 형식 | 이번 범위의 출력 대상 | 조건 기준 |
| --- | --- | --- |
| CSV | 전체 실행의 웰 목록, 마커 열 포함 | 사용자가 선택한 완료 결과의 사이클·정규화·배경·판정 |
| PDF / XLSX | 전체 실행 보고서 | CSV와 같은 결과 버전. 마지막 사이클 자동 대체 금지 |
| PNG | 전체 분석 차트 또는 현재 선택 마커 차트 | 렌더된 차트와 완료 결과의 버전이 일치해야 함 |

CSV/PDF/XLSX 메뉴에는 “전체 실행”, PNG에는 “현재 차트”를 표시한다. 선택 웰·그룹 필터는 보고서 범위를 바꾸지 않는다. PNG에는 표시 중인 필터를 명시한다. 파일명에는 범위·사이클을, 파일 내부 메타데이터에는 결과 버전·계산 조건을 남긴다(CSV는 기존 데이터 열을 유지하고 메타데이터 열 추가, PDF/XLSX는 보고서 정보 영역, PNG는 캡션).

- 현재 보기만 다르고 저장 결과의 입력은 유효하면 “현재 조건으로 재분석 후 내보내기 / 마지막 분석 조건으로 내보내기 / 취소”를 제공한다. 두 번째 선택은 화면을 조용히 변경하지 않는다. PNG는 이전 결과를 별도 렌더하지 않으므로 마지막 조건으로 보기를 이동한 후 내보내도록 안내한다.
- 입력 버전이 달라졌거나 조건을 알 수 없는 기존 결과는 마지막 조건 내보내기를 제공하지 않는다. 재분석이 먼저 필요하다. 단순 수치 열만 바꾼 혼합 결과는 허용하지 않는다.
- 수용 기준 A: 40사이클 판정에서 20사이클을 보고 “현재 조건”을 선택하면 20에서 재분석하고 CSV/PDF/XLSX의 수치·판정·메타데이터가 그 결과와 일치한다.
- 수용 기준 B: 같은 상황에서 “마지막 분석 조건”을 선택하면 파일은 40사이클 결과와 일치하고 화면은 20사이클을 유지한다. 동일 결과 버전의 공통 웰은 형식 간 유전자형이 같고 수치는 표시 반올림 범위 내에서 일치한다.
- 수용 기준 C: 단일/마커별 PNG, 렌더 지연, 정규화·배경만 변경, 수동 유형 변경, 재분석 실패, 동시 결과 교체(409), `legacy_unknown`을 검증한다. 실제 파일의 내용을 검사하며 메뉴 설명만으로 완료 처리하지 않는다.

### UX-03. 키보드 상호작용 보존 — P1 / F04

- `defaultPrevented`인 이벤트는 전역 처리하지 않는다. 위젯이 소유한 키는 해당 위젯에서 처리하고 전파를 중단한다. 모든 `button`을 일괄 제외하는 방식은 사용하지 않는다.
- 탭은 선택 상태·연결 패널을 제공하고, 방향키로 탭 이동, Enter/Space로 활성화한다. 이미 구현된 웰 그리드의 단일 진입점·방향키 이동·Shift 범위 선택은 회귀 검증한다.
- 결과 셀을 키보드로 선택할 수 있게 하고, 웰 주소·유전자형·선택 상태를 접근 가능한 이름으로 제공한다.
- 수용 기준: 아래 키 매트릭스대로 작동한다. 설정 탭의 Space는 탭을 열고, 그리드 이동·선택은 사이클이나 재생을 바꾸지 않는다. 모달 종료 후 호출 위치로 포커스가 돌아온다.

| 포커스 영역 | 영역이 소유하는 키 | 허용하는 앱 단축키 |
| --- | --- | --- |
| 입력·편집 가능 텍스트 | 텍스트 입력·기본 편집 키 | 없음. Ctrl/Cmd+Z도 텍스트 편집 유지 |
| 탭·일반 버튼·메뉴·대화상자 | Space/Enter, 해당 위젯 방향키·Esc | 분석 단축키 차단 |
| 웰 그리드·결과 그리드 | 방향키/Home/End, Shift+방향키, Enter/Space 선택, Esc 해제 | 1~7 유형 지정, Ctrl/Cmd+E 내보내기, Ctrl/Cmd+Z 및 redo 조합. 세션·선택·상태 조건 충족 시만 실행 |
| 분석 화면의 비대화형 배경 | 해당 없음 | 기존 재생·사이클·유형 지정·내보내기 단축키. 분석 외 화면에서는 재생·사이클·유형 지정 차단 |

언어/테마·도움말 단축키는 입력·메뉴·대화상자 외에서 유지한다. 내보내기와 실행취소 단축키는 버튼과 동일한 UX-02·UX-10 검증/오류 처리를 사용한다.

### UX-04. 전체 분석과 마커 배정 안내 구분 — P2 / F06

- 마커가 없을 때는 “전체 플레이트를 하나의 마커로 분석 중”으로 안내한다.
- 명시적 마커가 있을 때만 “마커 미배정 웰”과 마커별 분석 제외 범위를 안내한다. 빈 웰·제외 웰과 마커 미배정은 별도 상태로 취급한다.
- 수용 기준: 마커 0개인 예제에서 전체 분석 제외 안내가 나오지 않는다. 마커 생성·배정·삭제 후 안내와 실제 분석 대상 수가 일치한다.

### UX-05. 실패 안내와 복구 — P2 / F07

- 프리셋 저장·삭제·목록 조회와 최근 세션 열기에 진행·성공·실패 상태를 제공한다. 실패 시 입력과 선택을 보존한다.
- 최근 세션이 삭제됐거나 접근 불가하면 안내와 목록 새로고침을 제공한다. 인증 만료는 재인증 경로로 연결한다.
- 여러 파일 업로드는 파일별 이름·상태·이유·성공한 세션 ID를 `upload-job-store`에 유지한다. 오류가 있으면 자동 이동하지 않고 결과 요약과 “프로젝트로 이동”을 제공한다. 상태는 탭 이동을 넘어 유지하되 새로고침·로그아웃 시 초기화되는 메모리 상태다. 진행률은 실측 값 또는 명확한 단계 안내를 사용한다.
- 이번 범위는 실패 내역 보존과 수동 파일 재선택 안내까지다. `File` 객체/바이트 보존, 서버 성공 후 응답 유실 판별, 중복 방지 키를 갖춘 자동 재시도는 별도 후속 기능으로 분리한다. 성공 여부 불명확한 항목은 성공/실패로 단정하지 않고 세션 목록 확인을 안내한다.
- 수용 기준: 500·네트워크 실패·권한 오류가 화면에 표시된다. 프리셋 중복 저장을 막고 재시도 후 성공 상태로 전환된다. 배치 업로드는 부분 성공과 응답 유실을 구분하고, 오류 정보가 탭 이동으로 사라지지 않는다.

### UX-06. 작업 위치 복원 — P2 / F08

- 신규 `navigation-store`가 세션 ID·탭·서브화면·선택 마커·절대 사이클과 `restoring/ready/error`를 소유하고 URL과 동기화한다. `App`·`AnalysisWorkspace`·`MultiMarkerAnalysisPanel`의 탐색 로컬 상태는 이 값을 참조하도록 이관한다. 실행 데이터는 `session-store`, 판정 스냅샷은 UX-02의 `analysis-store`, 선택 웰은 기존 `selection-store`가 소유한다.
- URL은 `session/tab/surface/marker/cycle` 키를 사용한다. 인증 확인 → 세션 접근 및 데이터 로드 → 마커·저장 판정 로드 → URL 유효성/읽기 구간 검증 → 설정과 사이클을 일괄 적용 → `ready` 순으로 복원한다. 서버 재시작 후 DB 복원 경로도 검증하며, 404만으로 데이터 영구 소실이라고 단정하지 않는다.
- 복원 우선순위는 탐색값의 경우 유효 URL → 저장 판정 사이클/유효 기본 마커 → 데이터 기본값이다. 정규화·배경·계산 매개변수는 같은 탭의 세션별 보기 캐시 → 저장 판정 컨텍스트 → 데이터에 허용된 기본값 순이다. 캐시는 `sessionStorage`에 사용자·세션별로 분리하고 로그아웃 시 지운다. 언어·테마는 기존 영속 설정을 유지한다.
- 캐시 또는 URL과 저장 판정이 다르면 보기만 복원하고 “마지막 분석과 다름”으로 표시한다. 복원 과정에서는 판정을 다시 계산하거나 덮어쓰지 않는다. 새 업로드의 최초 자동 분석과 구별하며, 이후 사용자 입력에서 기존 단일/마커별 실행 정책을 재개한다.
- `restoring` 동안 `CycleControl`의 기본 구간·사이클 초기화, `App`의 ROX 자동 설정, 마커별 자동 분석, URL 재기록을 막는다. 절대 사이클로 사전 판독/증폭/사후 판독 구간과 상대 슬라이더 값을 함께 복원한다. 늦게 도착한 이전 세션 요청은 무시한다.
- 탭·서브화면·마커 이동은 `pushState`, 연속 사이클 조정은 `replaceState`를 사용한다. `popstate`는 재기록 없이 복원한다. 재생은 항상 정지 상태로 복원한다. 삭제된 마커·유효하지 않은 사이클은 사유를 표시하고 위 우선순위로 대체한다.
- 토큰·샘플명·원시 데이터는 URL에 넣지 않는다. ASG 런치 토큰 제거 및 경로 접두사 동작을 보존한다.
- 401은 모드별 재인증, 403은 접근 불가, 404는 실행을 찾을 수 없음과 목록 이동, 네트워크/5xx는 재시도로 구분한다. 해당 API가 접근 대상을 숨기려고 404를 반환하는 정책은 유지한다. 실패 중 다른 세션의 결과를 노출하지 않는다.
- 수용 기준: 단일/마커별 화면의 새로고침·뒤로 가기, ROX 수동 해제, 사후 판독 구간, 삭제된 마커, 유효하지 않은 사이클, 권한 만료, 서버 재시작 후 복원을 검증한다. 복원만으로 분석 API가 호출되지 않고 저장 판정 버전이 유지되어야 한다. 캐시와 저장 판정이 다른 경우 불일치 배지가 표시된다.

### UX-10. 수동 웰 유형 실행취소 연결 — P2 / F14

- 기존 훅에 이력 등록 호출이 없는 상태를 수정 대상으로 명시한다. 이력은 세션별 공통 `undo-store`로 통합하고 버튼·키보드·컨텍스트 메뉴의 수동 유형 변경이 동일 변경 경로를 사용한다.
- 범위는 수동 웰 유형의 단일/다중 변경으로 한정한다. 마커 삭제·배정·알고리즘·축 설정·분석 결과 이력까지 되돌리지 않는다. 연속된 다중 웰 변경은 한 단계로 묶고 전후 상태를 기록한다.
- 서버 변경 성공 후에만 이력 포인터를 이동한다. undo/redo 실패 시 포인터를 보존하고 오류를 표시한다. 이력은 최대 50단계, 새로고침·세션 변경·로그아웃 시 초기화하며 다른 세션에 적용하지 않는다. 충돌하는 외부 변경을 감지하면 이력을 무효화하고 안내한다.
- undo/redo 역시 입력 버전을 갱신한다. 이전 분석을 현재 유효 결과라고 간주하지 않고 UX-02의 재분석 정책을 따른다.
- 수용 기준: 단일/마커별 화면에서 유형 변경 → 취소 → 재실행이 화면·서버에 동일하게 반영된다. API 실패·다른 세션 이동·헤더와 단축키의 동일 이력 사용을 검증한다.

## 6. 화면 구성안

### 헤더와 탐색 — UX-07 / P2 / F05

- 첫 영역은 브랜드와 현재 실행, 두 번째 영역은 작업·계정으로 구성한다. 공간이 부족하면 자연스럽게 두 줄로 전환한다.
- 내보내기는 주요 작업으로 유지한다. 장비·웰 수 등 부가 정보와 계정 작업은 요약 메뉴로 이동할 수 있다. 중요한 경고는 요약 후에도 존재가 드러나야 한다.
- 1280px 이상은 분석 2열, 768~1279px는 1열과 재배치된 툴바, 390~767px는 탐색·검토 중심 1열을 기본안으로 한다. 고밀도 플레이트·표의 가로 스크롤은 패널 내부에 한정한다.
- 수용 기준: 390·768·1024·1280·1440px에서 문서 전체 가로 오버플로와 버튼 글자의 한 글자 단위 줄바꿈이 없다. 긴 실행명·다수 경고·ASG 연결 컨텍스트에서도 검증한다.

### 분석 작업 공간 — UX-08 / P2 / F09

- 상단에 현재 범위·사이클·분석 상태와 분석/재분석 액션을 모은다. 상세 축·임계값 편집은 접이식 영역으로 제공하되 적용 중인 핵심 조건은 요약해 남긴다.
- 데스크톱은 왼쪽 산점도, 오른쪽 플레이트와 선택 웰 상세를 세로 배치한다. 오른쪽 카드 높이를 산점도 높이에 강제로 맞추지 않는다. 결과표와 증폭 곡선은 아래에 배치한다.
- 설정 화면은 기본값·프리셋 관리, 분석 화면은 현재 실행의 조건 확인·조정으로 역할을 구분한다. 양쪽 컨트롤은 동일 상태를 참조한다.
- 수용 기준: 1440×1000·브라우저 100% 확대·96웰·상세 설정 접힘 상태에서 산점도와 플레이트를 함께 확인하고, 웰 선택 시 주소·샘플·판정·신뢰도 요약을 추가 페이지 스크롤 없이 확인한다. 증폭 곡선 전체는 펼쳐서 확인할 수 있다. 384웰과 다수 경고는 패널 내부 스크롤을 허용한다. 단일/마커별 선택 동기화를 유지하고 재분석은 UX-02, 실행취소는 UX-10 기준으로 검증한다.

### 품질·표현·기타 화면 — UX-09 / P2 / F10

- 품질의 플래그 웰을 선택하면 `navigation-store`를 통해 해당 세션/마커의 분석 화면과 웰 상세로 이동한다. 기존 필터 때문에 숨겨져 있으면 임시 표시 상태를 알린다. 마커 미배정 웰은 플레이트 설정의 해당 웰로 이동한다. 곡선 기반 품질 점수와 특정 판정 조건의 QC는 서로 다른 지표로 설명한다.
- 유전자형은 색상 외에 심볼·짧은 라벨을 병행한다. 다크 모드 NTC에는 밝은 테두리나 구분 가능한 심볼을 적용한다. 웰 주소 `A1`과 유전자형 약자의 역할을 시각적으로 구분한다.
- 동작·오류·도움말 문구를 기존 한/영 번역 체계로 통합한다. 장비·유전자·표준 약어와 원문 참고문헌은 유지할 수 있다. 정규화 안내는 장비명 단정 대신 해당 데이터의 사용 가능 기준 채널과 적용 상태를 설명한다.
- 비교 화면의 실행 선택에는 파일명·일시 등 구분 정보를 제공한다. 동일한 장비/예제 이름만으로 항목을 식별하게 하지 않는다.
- 로그인·프로토콜·프로젝트·라이브러리·관리 화면은 공통 상태·포커스·반응형 원칙을 적용한다. 별도 근거 없이 기능이나 업무 구조를 바꾸지 않는다.
- 수용 기준: 주요 유형은 흑백에서도 텍스트/심볼로 구분된다. 일반 텍스트 대비 4.5:1, 큰 텍스트 및 필요한 UI 경계·표식 대비 3:1을 목표로 측정한다. 한국어/영어 전환 시 동작 문구가 일치한다.

기간과 담당자는 착수 시 산정한다. 요구사항 단위로 변경을 묶고, 각 변경은 관련 회귀 테스트와 전후 화면을 함께 검토한다.

UX-03의 undo/redo 기능 검증은 UX-10과 함께 2단계에서 마감한다. 1단계는 입력 위젯의 기본 키와 분석 단축키 충돌 해소를 완료한다. 계약 변경은 기존 소비자의 오류 처리까지 연결한 상태로 배포하며, 프론트만 먼저 바꾸어 서버가 지원하지 않는 결과 조건을 추정하지 않는다.

## 8. 검증 계획

- 단위/컴포넌트: QC 상태표·호환 응답, 분석 컨텍스트 불일치 판정, 복원 우선순위, 키 매트릭스, 이력 포인터의 실패 시 보존을 검증한다.
- 백엔드: 컨텍스트 왕복 저장, 구버전 결과 역직렬화, 입력/결과 버전 검증, 늦은 계산의 덮어쓰기 방지, 마커별 QC를 검증한다. CSV/PDF/XLSX는 동일 fixture·결과 버전의 수치/판정/메타데이터를 실제 파일에서 비교한다. PDF 계산 경로는 `app/routers/data.py`도 포함한다.
- Playwright: F01~F14에 연결된 수용 기준을 검증한다. 단일/마커별 분석, 정상·빈·실패 상태, 새로고침, 사전/사후 판독 구간, 키보드 조작, 다운로드 파일 검사를 포함한다. 코드로만 발견한 F11~F14는 재현 테스트부터 작성한다.
- 화면 검증: 분석·플레이트 설정·헤더는 다섯 화면 폭 × 한/영 × 라이트/다크를 확인한다. 기타 화면은 390·1024·1440px에서 검사하고 결함이 있으면 범위를 확장한다.
- 추가 데이터: 합성 96웰 외 384웰, 긴 실행명, 여러 마커, NTC 정상·오염·미존재, 요청 지연·실패를 포함한다. 실제 장비 파일은 허용된 비식별 fixture만 사용한다.
- ASG: 권한 없는 저장 버튼 비활성, 저장 상태, 런치 만료, 경로 접두사를 별도 검증한다. 이번 리뷰에서 통과했다고 간주하지 않는다.
- 코드 변경 시 프론트엔드 build/lint와 관련 Vitest·E2E를 실행한다. API 변경 시 관련 pytest를 추가 실행한다. 기존 실패는 이번 변경과 구분해 기록한다.
- 측정 지표: P1 재현 시나리오 실패 0건, 같은 결과 버전의 형식 간 조건 불일치 0건, 지원 폭의 문서 가로 오버플로 0건, 지정 실패 시나리오의 무응답 UI 0건, 복원 중 분석 실행 0건을 목표로 한다. 완료 주장은 실제 실행 결과로 남긴다.

## 10. 교차 리뷰 반영 기록

- 반영: 저장 조건 부재, PDF/CSV/XLSX 조건 혼합, NTC 응답 의미와 상승 감지 문구, 마커별 권위 QC, 복원 초기화 충돌, 키보드 허용 범위, 실행취소 연결 공백, 문서 기준 충돌.
- 선택한 정책: 마커별 자동 재분석은 유지하되 복원 중 금지한다. “모든 분석을 수동으로 전환” 제안은 기존 작업 흐름 변경을 줄이기 위해 채택하지 않았다. 현재 사이클 재분석과 추천 사이클 분석은 구분한다.
- 정정: 서버 재시작 시 데이터가 반드시 소실된다는 지적은 DB 복원 경로(`app/main.py`, `app/db.py`)와 맞지 않아 제외했다.
- 범위 축소: 파일 자동 재시도·과거 분석 버전 탐색은 후속 과제로 남긴다. 이번 문서는 최신 판정의 검증 가능한 저장·출력과 탭 이동 중 오류 내역 유지까지 다룬다.
