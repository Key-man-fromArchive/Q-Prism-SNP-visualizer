# P0-R0-T1 — Runtime/auth dependency remediation

Date: 2026-09-07. Scope approved by user; implementation on `ux-followup/p0-preflight`.

## Changes and compatibility

- Replaced python-jose 3.5.0 (mandatory vulnerable ecdsa dependency) with PyJWT 2.13.0; patched python-multipart 0.0.29 to 0.0.32.
- Kept HS256 allowlist, token issuer claims, local/ASG lifetime, cookie flags/path, ASG mode boundary, and authorization dependencies unchanged.
- Explicitly preserved python-jose's integer-shaped `iat` policy (future values accepted) instead of silently adopting PyJWT's stricter future-iat default. Legacy tokens without `exp` remain accepted; application-issued tokens still always expire. No new role policy added.
- Malformed signed username/role types now return invalid-token rather than leaking a Pydantic exception. Signature, algorithm, expiry, nbf, audience, jti and subject checks remain enforced.
- Added pinned pip-audit, ruff and mypy development diagnostics. No vulnerability exemptions or ignored audit IDs.

Migration regression includes an actual python-jose 3.5.0-generated golden token with a deliberately synthetic public fixture key; other adversarial tokens use independent standard-library HMAC, not the replacement decoder's signer.
