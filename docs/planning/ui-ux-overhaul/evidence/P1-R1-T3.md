# P1-R1-T3 — Immutable calculation and atomic publication

Baseline: `0b4157c`; branch `ux-followup/p1-contracts`, 2026-09-07.

## Implementation and scope

- Acceptance validates actual domain/background inputs, checks expected input
  revision, applies the existing explicit-ploidy command when applicable, then
  captures deep copies of data/request/regions and effective imported/manual
  well types. Each accepted request receives a monotonic per-session sequence.
- Pure calculation runs in Starlette/AnyIO's bounded worker pool. It reads no
  live session stores and performs no database writes. Scientific clustering,
  normalization, background subtraction and ratio-origin implementations are
  unchanged; the original whole-plate/region calculations receive copied inputs.
- Publication checks session-object identity, publication-state identity,
  sequence and input revision. DB save must succeed before memory replacement.
  Newer failed/cancelled requests still supersede older work. Failure retains
  the previous completed result. Cancelled workers can finish locally but cannot
  publish; `BaseException` cleanup prevents a stuck latest pending status.
- State has a session owner identity; replacement/restoration cannot inherit
  old pending/failed status. Parent-approved `sample.py` changes clear request
  state after committed deletion and expose additive status in session info.
- GET/POST cluster and session info expose `analysis_pending` plus
  `analysis_status: idle | computing | completed | failed`, independently of
  retained result provenance and current input revision.

## Provenance decisions

Context records actual cycle, requested ROX, actual positive-reference
normalization availability, resolved background, effective algorithm, complete
threshold defaults, ploidy, requested cluster-count input, effective types,
excluded wells, origin and actual output window. Whole-plate and region scope
are explicit. `n_clusters_applied` is false for AUTO/manual-threshold regions;
no fitted AUTO K is invented. Regions retain independently resolved inherited
settings and heterogeneous ploidy. Requested algorithm is separately preserved
for future client setting comparison/restoration.

Manual boundaries mean actual threshold, regardless of nominal request;
different region algorithms produce context-only `mixed`. The calculation enum
and legacy result algorithm echo are unchanged. Cycle zero retains the existing
last-cycle sentinel; a zero-only acquisition correctly stores actual zero.
Normalization is true only when enabled and at least one captured-cycle reading
has a positive effective reference; individual raw fallback is unchanged.

## Deployment and downstream boundaries

This is **single-process coordination**, not multi-worker/process CAS. The
short process-global input/DB lock composes with per-session publication locks;
no lock is held while awaiting scientific calculation. Existing legacy DB
writers outside this boundary remain outside its guarantee. No unbounded
per-request thread creation, dependencies, host packages or live databases were
introduced. `db.py` did not need further changes: T1 rollback is reused.

QC/export consumers must honor current revision and latest analysis status;
the retained result is not automatically current after a failed request.
Export snapshot validation is a later task. `python-pro` guided typed contracts
and bounded helpers. Parent taskbook/appendix changes are not in this commit.
