## Contract implementation

Current plate NTC and stored judgment are separate computations over one detached snapshot. The input lock captures raw session data, completed result, current effective types and latest request status together; computations run after release. Suggest-cycle also copies its input under that boundary. Authorization precedes capture.

- NTC responses retain `ok/wells`, adding `status`, nullable `flagged`, structured `reason`, plate scope and actual requested cycle/ROX/background plus actual normalization availability. Declared imported/manual NTC wells remain listed when readings are absent. Missing/nonfinite signals are null, not invented zeros. A nonpositive usable plate median means `missing_reference`; absent ROX alone preserves raw fallback.
- The existing measured-coordinate contamination rule is unchanged: signal >= 0.3 × positive upper-middle plate median. Finite readings define the usable reference. Warning takes precedence over incomplete evaluation, then insufficient, no NTC, and fully evaluated OK. Positive-control warnings remain measured-coordinate checks.
- Judgment returns captured `input_revision`, `current_input_revision`, result revision, context, `context_status`, explicit `judgment_status/reason`, and independent latest analysis status/pending. Verified historical metrics use stored conditions, captured types/origin/exclusions and region results, never current manual edits or view settings. Stale results remain inspectable.
- Contextless/missing results expose null separation and readable stored counts, never provisional ratio calls presented as completed judgment. Context that exists but lacks well-formed origin/types/exclusions similarly yields `legacy_unknown/context_missing`; context presence remains `context_status=verified`. Strict provenance validation does not invent zero origins or empty maps. The original model and retained context are not rewritten.
- Whole-plate separation remains measured normalized coordinates at stored conditions; per-marker separation remains origin-shifted, as before. Captured exclusions are respected. Marker QC is authoritative, with null pooled separation and captured names/ploidies; call-rate denominator and NTC/Undetermined semantics are preserved.
- Onset status annotates actual evaluation: insufficient windows (<9 derivative readings), missing/incomplete/nonfinite curves, no candidates, evaluated non-detection, or actual detection. A valid finite positive detection is retained even with another incomplete curve. Invalid curves cannot manufacture detection. The finite-data derivative algorithm, thresholds, candidate selection and suggested-cycle numerics are unchanged.

This is the backend contract, not a claim that downstream QC UI/export work is finished. No frontend, dependency, server, operational database or host-package changes were made. No changes to `models.py` were necessary: existing QC-local models and additive dictionaries represent the wire contract.
