## Delivered contract

- One in-memory `undo-store` records immutable exact manual maps before/after successful commands, at most 50. Successful new edits discard redo; no-op edits do not write or consume history. Failed edits/undo/redo retain the pointer and values. Pending is shared across all callers.
- Keyboard, analysis popup, Plate Setup and Header use `manual-commands`. Requests pin authenticated owner, session ID, entry generation and command ticket. Session reset/reentry/logout synchronously invalidate history; late successes, failures and conflicts cannot publish to a new owner/entry.
- Each mutation uses bulk replacement with `expected_input_revision`. Conflicts invalidate history and refresh without retrying the mutation; failed refresh leaves input revision explicitly unknown. Accepted changes advance revision and dispatch one `welltypes-changed` event, retaining existing single-result-stale/multi-analysis policy. Marker/group/algorithm/view changes are not undo commands.
- GET/POST/PUT well-type responses add exact `manual_assignments` and `input_revision` under the same input lock as mutation/response capture. Existing merged/imported fields are unchanged. Explicit manual values equal to imported values, absent overrides, no-ops, rollback and CAS are tested; no subtraction-based reconstruction.
- Shared display loading guards owner/session/entry, request sequence and revision before global assignments or imported metadata publish. Header buttons subscribe to the same history as platform-primary undo, Shift-primary redo and Windows/Linux Ctrl+Y. Existing editable, composition, repeat, modal/menu and native-widget ownership guards remain.
- Fixed KO/EN pending/error/conflict text does not expose server details. A separate full-width polite/atomic live region avoids squeezing Header actions. Selection is retained on failure; existing successful popup selection policy remains.
