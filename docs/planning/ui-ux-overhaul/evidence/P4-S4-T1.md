## Implemented contract

- Login fields have native username/current-password autocomplete, names and labels; Enter submits the form, busy state is exposed, duplicate requests are suppressed. A held response cannot set the user or disclose an error after unmount/auth-generation/mode changes. Errors use a safe localized message. This is a UI/store publication guard, **not** a claim to cancel HTTP Set-Cookie delivery.
- Protocol is keyed to auth generation, session ID and entry generation. Every GET/save also captures and checks the live identity immediately before publication, independent of passive React cleanup. Lookup, lookup failure/retry, empty, saving, saved and failed-save states are distinct. Save failure retains edits; Cancel restores the accepted local draft; editing after save clears the saved claim. Native form submit, labelled step inputs/delete buttons and disabled busy controls preserve existing POST semantics. Failure has an icon, alert role, danger border/tint and readable theme text.
- Protocol's large editable table scrolls inside a labelled/focusable bounded region; action buttons wrap. Settings preset controls have accessible names, native save submission and min-width containment for long names, using the existing preset lifecycle and single settings store.
- Upload progress exposes a labelled progressbar and live status. Existing tickets/cancellation/partial failure/unknown-outcome records remain unchanged. Template links still use `runtimeAssetPath`; only presentation changed. Help is a semantic button with pointer/keyboard open and Escape/blur dismissal, bounded tooltips and conditional descriptive ID references. Quick Start and format guidance stack at narrow widths instead of forcing four tiny columns.
