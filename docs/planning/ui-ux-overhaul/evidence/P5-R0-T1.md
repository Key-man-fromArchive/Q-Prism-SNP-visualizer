# P5-R0-T1 — Compatibility and regression evidence

This task is test-only. No backend, frontend, parser, calculation, export, or
runtime product behavior was changed.

## Automated evidence

- Backend focused compatibility suite: **12 passed**.
- Full backend suite: **755 passed, 39 warnings, 2 subtests**.
- Exact browser spec `tests/26-asg-compatibility.spec.ts`: **5 passed**.
- `git diff --check`: passed.

The coverage exercises authentication and expiry handling, owner/session and
snapshot isolation, CSV/PDF/XLSX/ASG export denial before disclosure, upload
rejection without persisted jobs or temporary files, and ZIP absolute-path,
backslash-traversal, entry-count, compression-ratio, and zero-entry branches.
It also covers a two-process restart with owner-bound result metadata and a
genuine pre-v3 SQLite migration reopened twice while preserving parent/child
relationships and treating legacy context as unknown.

## ASG and proxy boundaries

All fixtures use synthetic identifiers and credentials. Backend ASG external
transport is patched/test-injected; the suite verifies the request contract and
does not issue a real POST. The browser save endpoint is mocked, and the exact
browser spec asserts a single consumed launch token, removal after use, and no
token or credential leakage in URLs or captured artifacts. The proxy harness
strips `/snp-analyze` before forwarding while browser URLs remain mounted under
that prefix, covering assets, auth, configuration, login cookies, and template
download paths.

Cross-user export and snapshot attempts are rejected before rendering or ASG
transport, with renderer/transport call counts remaining zero. The E2E test
alone does not prove backend outbound transport behavior; that boundary is
proved by the combined backend compatibility test with the external transport
patched.

No actual ASG service, private sample data, secrets, tokens, or generated
browser artifacts are included in this evidence or the repository changes.
